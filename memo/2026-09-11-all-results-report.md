## 0. 먼저 용어를 세운다

이 보고서를 읽는 데 필요한 말만 여기서 정의한다.

- **ATE (average treatment effect, 평균 처치효과)**: 모두를 처치했을 때의 평균 결과에서 모두를
  처치하지 않았을 때의 평균 결과를 뺀 값이다. 아래 모든 실험에서 참값은 $1$로 고정되어 있다.
  따라서 "오차"는 항상 $|\hat\theta - 1|$을 뜻한다.
- **$X$**: 관측되는 공변량. **$W$**: 관측되는 대리변수(proxy) 블록들의 모음. **$U$**: 관측되지 않는
  교란변수. **$A$**: 처치. **$Y$**: 결과.
- **raw $(X, W)$ 보정**: $X$와 모든 $W$ 블록을 그대로 넣어 조정한 추정치다. 이 논문이 이겨야 하는
  가장 중요한 상대다. 아무 이론 없이 "있는 것 다 넣기"에 해당하기 때문이다.
- **oracle $(X, U, C)$ 보정**: 관측 불가능한 $U$를 실제로 넣어 조정한 추정치다. 현실에서는 쓸 수
  없고, 도달 가능한 성능의 상한 기준으로만 쓴다.
- **held-out block set $S$**: PROBE가 감사(audit) 대상으로 빼 두는 블록 집합이다.
- **표현(representation) $Z$**: 남은 입력 $(X, W_{-S})$만으로 만든 함수값이다. PROBE는 $Z$로 조정한다.
- **감사 격차(audit gap)**: $S$를 알 때와 모를 때의 처치 예측 정확도 차이다. 형식으로는
  $D^2 = \mathbb E\big[\{P(A=1\mid T_S, Z) - P(A=1\mid Z)\}^2\big]$이고, 실제로는 두 개의 critic
  (예측기)의 Brier 위험(제곱오차)의 차이로 추정한다. $Z$가 $S$를 완전히 균형 맞추면 $D^2 = 0$이다.
- **critic**: 처치 확률을 예측하는 신경망이다. base critic은 $Z$만 보고, augmented critic은 $Z$와
  $T_S$를 함께 본다. 감사 격차는 두 critic의 성능 차이다.

## 1. 한 줄 결론

라운드 11의 현행 엄격 판정은 **implementation PASS, diagnostic computation PASS, performance
FAIL**이다. 라운드 10 사후 감사에서 드러난 checkpoint–cell 결속 결함을 고친 뒤 세 실행을 새 run ID로
다시 생성했고, `results/dgp_f_r11_verdicts.json`이 한 증거 묶음으로 검증했다.

**첫째, 구현 증거가 이제 닫힌다.** 원고 모드 계수 $25$칸, 변형 모드 $25$칸, 원고 stage 4 $27$칸의
각 checkpoint가 `protocol_id`, `run_id`, canonical `cell_key`를 결과 record와 저장 payload 양쪽에
담는다. verifier는 두 곳을 실제 소유 cell과 비교하고, 모든 data seed의 split 불변식을 독립 재계산하며,
source role과 bundle digest도 다시 계산한다. $77$개 checkpoint와 세 source snapshot이 모두 통과했다.

**둘째, 계수 진단은 “탐색만 실패한다”는 이전 결론을 반박한다.** 모집단 목적과 참 확률을 쓴
유한표본 목적은 다섯 자료 모두에서 좋은 격자점을 골랐다. 그러나 같은 split-sample refit 규약의 두 critic으로
모든 격자점과 학습점을 다시 채점하면 좋은 점을 고른 자료는 $1/5$뿐이다. 실제 원고 모드의
유한후보 선택은 $0/5$, 변형 모드는 $1/5$만 인과 성공 기준을 만족했다. optimizer의 목적 regret은
대부분 매우 작았는데도 인과 편향은 컸다. 따라서 현재 근거가 지목하는 병목은 **critic이 만든 경험적
목적의 순위 해상도**이며, optimizer도 기여하지만 단독 원인으로 분리되지는 않았다.

**셋째, stage 4에서는 표본이 커질수록 좋아지지만 동결 성능 기준에는 미달한다.** 독립 반복 단위인 data
seed 안에서 optimizer seed를 먼저 중앙값으로 합친 뒤, $n=48{,}000$에서
$|\tau_Z-1|$의 data-seed 중앙값은 $0.100149$, p90은 $0.111593$이다. 동결 기준 $0.05$, $0.10$을
각각 넘으므로 performance FAIL이다. 아홉 optimizer 칸을 한데 모은 p90 $0.180298$은 변동 진단값이지
판정 통계량이 아니다.

**넷째, diagnostic computation PASS와 과학적 가설의 상태를 분리한다.** 모집단 격자와 참 확률 유한표본
격자가 좋은 후보를 고른다는 가설은 지지된다. optimizer가 자기 유한후보 최소값을 크게 놓친다는 가설은
지지되지 않는다. fitted critic의 어긋남을 critic 근사와 표본 변동 중 하나로 귀속하는 가설은 아직
미해결이다. PASS는 이 네 진단을 계산했다는 뜻이지 방법의 인과 성공을 뜻하지 않는다. 상세는 7d절이다.

## 2. 라운드 5 지적에 대한 수정

다섯 번째 리뷰는 네 가지를 지적했다. 각각을 어떻게 고쳤고 무엇으로 확인했는지 적는다.

### F23. 퇴화한 감사 통계량이 스크린을 통과하던 문제

**지적한 내용**: `screen_decision`이 격차가 NaN이거나, 표준오차가 NaN이거나,
격차 $=100$에 표준오차 $=\infty$인 경우에도 `screen_pass=True`를 돌려줬다.

**원인**: 판정이 `refit_gap > 0.02 + 2 * refit_se` 하나의 비교로만 이루어져 있었다. NaN과의 비교는
파이썬에서 항상 거짓이므로, 통계량이 망가지면 조건이 거짓이 되고 그대로 통과했다. `inf`가 섞인
경우도 문턱값이 무한대가 되어 통과했다.

**고친 방법**: 비교 이전에 유한성을 먼저 요구한다. 격차와 표준오차가 모두 유한하고 표준오차가 음수가
아닐 때만 문턱값 비교로 넘어가고, 그렇지 않으면 `audit statistic not finite` 사유로 거절한다.
구현 위치는 `code/probe_brier_neural.py`의 `screen_decision`이다.

**확인**: `code/test_probe_brier_neural.py`에 네 개의 퇴화 사례를 추가했고 모두 거절된다.

```
F23 the screen rejects a non-finite gap                       pass=False
F23 the screen rejects a non-finite standard error            pass=False
F23 the screen rejects an infinite standard error beside ...  pass=False
F23 the screen rejects a negative standard error              pass=False
```

### F24. 체크포인트 선택이 더 음수인 검증 격차를 선호하던 문제

**지적한 내용**: 학습 중 에폭을 고를 때 검증 격차가 작을수록 좋다고 보고 있었는데, 격차는 부호가
있는 값이라서 $-0.10$이 $-0.01$보다 "좋다"고 판정되었다. 그런데 모집단에서 $D^2 \ge 0$이므로 큰 음수
격차는 좋은 표현이 아니라 augmented critic이 망가졌다는 신호다. 라운드 4에서 관찰된
"검증 격차 $-0.0898$인데 재적합 감사는 $-0.00175$"가 정확히 이 증상이었다.

**고친 방법**: 순위 기준을 **부호 있는 격차가 아니라 0으로부터의 거리**로 바꿨다. 새 함수
`checkpoint_key(gap) = |gap|`이고, 유한하지 않은 격차는 항상 꼴찌다. 에폭 선택과 재시작(restart)
선택 두 곳 모두 같은 함수를 쓴다.

**라운드 6 후속 수정**: 개선 허용치 `MIN_DELTA`가 여전히 부호 있는 차이 $|{\rm gap} - {\rm best}|$에
걸려 있었다. 그러면 $+0.010$에서 $-0.010$으로 가는 것이 거리는 그대로인데 $0.02$의 개선으로
세어진다. 허용치를 **순위 키의 개선량** $|{\rm best}| - |{\rm gap}|$에 걸도록 고쳤고, 그 사례가
개선으로 세어지지 않는 것을 검사로 잠갔다.

**효과**: 단계 2에서 학습이 보고하는 검증 격차가 $0$ 근처로 왔다. 수정 전 v4 실행에서 같은 양이
$-0.0959$였다. 다만 5.3절에 적었듯 DGP A에서는 조기 종료가 하한에 붙는 부작용이 남아 있다.

### F25. F20을 "포함관계 복원"이라고 설명한 것, 그리고 분리 적합 비교의 결함

**지적한 내용 (라운드 5)**: 공유 파라미터로 바꾼 것을 "model class containment를 복원했다"고
적었는데, 이전 구현에서도 trunk의 구조가 같았으므로 함수 클래스 수준의 포함관계는 이미 성립했다.

**수용한다.** 정확한 서술은 다음과 같고, 코드 주석과 이 보고서를 그렇게 고쳤다.

> **공유 파라미터를 사용하는 학습 방식으로 변경했고, 이번 표본에서 성능이 개선됐다.**

**지적한 내용 (라운드 6)**: 비교군으로 넣은 `decoupled_critic_fit`이 base critic을 학습한 뒤
augmented critic에 복사하고 **복사한 base를 동결한 채 잔차 가지만 학습**했다. 이것은 augmented
critic 전체를 자기 손실로 최적화하는 것보다 제한된 문제이므로, 원고 4절이 요구하는 두 개의 독립적인
위험 최소화를 검증하지 못한다.

**수용하고 고쳤다.** augmented critic은 이제 base critic의 적합값에서 **초기화만** 받고, 모든
파라미터(복사된 trunk 포함)를 자기 손실만으로 학습한다. 동결 코드는 제거했고, 분리 적합 함수 안에
`requires_grad_(False)`가 없음을 검사로 잠갔다. 새 결과는 4절 단계 2에 있다.

### F26. 요약기가 서로 다른 코드 버전의 같은 칸을 독립 반복으로 세던 문제

**지적한 내용**: v3와 v4를 함께 요약하면 같은 두 replicate가 네 개의 반복으로 계산된다.

**고친 방법**: `load`에서 `(phase, dgp, n, replicate)`를 키로 중복을 탐지하고, 중복이 있으면 오류를
내고 멈춘다. 어느 두 파일에서 충돌이 났는지 메시지에 적는다.

**확인**:

```
duplicate cell ('pilot', 'A', 6000, 10000) in ../results/dgp_ae_pilot_v4.json
and ../results/dgp_ae_pilot_v3.json; summarize one code version at a time, or renumber the replicates
```

### F27. 리뷰가 지적하지 않았지만 같이 발견해서 고친 것

`AugmentedCritic.__init__`의 `d_z: int = Z_DIM`이 기본 인자였다. 기본 인자는 클래스가 정의되는
시점에 한 번만 평가되므로, 나중에 `Z_DIM`을 바꿔도 이 값은 4로 고정된다. 단계별 실험에서 3차원
표현을 쓰려다 형상 불일치로 드러났다. 호출 시점에 해석하도록 바꿨고, 재적합 평가기는 실제로 받은
표현의 열 수에 맞춰 critic을 만든다.

**라운드 6 후속 수정**: 새로 넣은 `decoupled_critic_fit`에는 전역 `Z_DIM` 의존이 남아 있었다. 같은
방식으로 실제 표현의 열 수를 쓰도록 고쳤다.

이 버그가 지금까지의 본 실행 결과를 오염시키지는 않았다. 본 실행은 모두 $Z_{\rm dim} = 4$를 썼기
때문이다.

## 3. 단계별 실험을 왜 이렇게 설계했는가

라운드 4까지의 문제는 숫자가 나빠도 **어디가 나쁜지 말할 수 없다**는 것이었다. PROBE 한 번의 실행에는
최소한 네 개의 독립적인 실패 지점이 들어 있다.

1. **평가기**: 감사 격차가 좋은 표현과 나쁜 표현을 실제로 구분하는가.
2. **학습기**: 그 격차를 줄이는 표현을 실제로 찾아내는가.
3. **추정기**: 표현이 주어졌을 때 인과효과를 정확히 추정하는가.
4. **전체**: 세 가지가 합쳐졌을 때 표본이 커지면서 수렴하는가.

이 넷이 한 숫자로 합쳐지면, 나쁜 결과가 나와도 평가기 탓인지 학습기 탓인지 알 수 없다.
리뷰가 요구한 대로 네 단계로 분리했고, 각 단계는 **앞 단계가 통과해야만 의미가 있다.**

**왜 design F인가**: design F는 정확한 균형 표현이 닫힌 형태로 알려진 유일한 설계다. 측정값
$M_j = U + e_j$를 $k$개 남기고 $Z_3 = \overline M_k + r I$로 두면, 균형은

$$r^2 - 3r + \tfrac{1}{k} = 0$$

일 때 **정확히** 성립한다. 여기서 $3$은 처치 방정식에서 $I$의 계수다. 유도는 이렇다.
$Z_3 = U + \bar e + rI$이고 $\mathrm{Var}(\bar e) = 1/k$일 때, 처치 지표
$V = U + 3I + 0.2X + 0.3C$에 대해 $\mathbb E[V \mid Z_3, U] = \mathbb E[V \mid Z_3]$가 성립하려면
$U$의 계수가 사라져야 하고, 그 조건이 $r^2 + 1/k = 3r$이다.

따라서 단계 1에서는 **맞는 답을 직접 넣어 볼 수 있다.** 다른 어떤 설계에서도 불가능한 검증이다.

**관측행을 누가 쓰는가.** 라운드 6에서 지적된 자료 겹침 때문에 이번 판은 행 사용을 명시하고 강제한다.
표현 학습 표본 안에서 행을 50/25/25로 나눈다.

| 분할 | 쓰는 곳 | 안 쓰는 곳 |
| --- | --- | --- |
| `fit` | 인코더 학습, 두 critic 학습 | 평가 |
| `val` | 에폭(checkpoint)과 restart 선택 | 평가 |
| `audit` | 감사 격차 평가 전용 | 인코더 학습, critic 학습, 선택 |
| 추정 표본 | 인과효과 추정(교차적합 AIPW) 전용 | 표현 학습의 어떤 단계에도 안 들어감 |

평가 함수는 인코더가 쓴 세 인덱스를 그대로 받고, 평가 전에 `audit`과 `fit`, `val`의 교집합이 0임을
검사한다. 겹침을 주입하면 `ValueError`로 멈춘다. 학습·초기·정확 표현의 비교는 같은 `audit` 행에서
한다. 모든 보정(PROBE, raw, oracle, $X$만)은 같은 교차적합 분할을 쓴다.

**계획서로부터의 의도적 이탈**: 이 단계별 실험은 표현을 선형 사상으로 제한하고 $Z$를 3차원으로 둔다.
계획서 8.4절은 신경망 인코더와 4차원을 지정한다. 이유는, 정확해가 선형 클래스 안에 들어 있으므로
학습이 실패하면 그것은 탐색의 실패이지 함수 클래스의 한계가 아님을 보장하기 위해서다.
**이 단계별 결과는 확증(confirmatory) 결과가 아니고 진단 결과다.** 계획서 0.5절의 동결 규칙에 따라,
여기서 얻은 숫자를 본 결과로 재사용하지 않는다.

## 4. 단계별 실험 결과

### 단계 1. 평가기 검증 (P1)

**기준값은 표본이 아니라 구조방정식에서 계산한다.** design F의 모든 변수는 독립 표준정규 17개의
고정 선형결합이므로, 어떤 표현 $Z$와 held-out 블록 $T_S$에 대해서도 $(V, L, Z, T_S)$의 공분산은
계수행렬의 곱으로 정확히 나온다. 여기서 $V$는 성향점수 지표, $L$은 결과 방정식에서 처치와 잡음을
뺀 부분이다. 그 위에서

- $D^2 = \mathbb E[\{P(A=1\mid T_S,Z) - P(A=1\mid Z)\}^2]$는 $(m_0, m_1) = (\mathbb E[V\mid Z],
  \mathbb E[V\mid Z,T_S])$가 이변량 정규이므로 2차원 Gauss–Hermite 구적으로,
- $\tau_Z = \mathbb E[\mathbb E(Y\mid A=1,Z) - \mathbb E(Y\mid A=0,Z)]$는 원고의 정의대로 조건부
  결과 평균의 차이를 평균낸 값이며, $Z$가 주어졌을 때 $(L, V)$가 이변량 정규이므로 1차원 구적으로

계산한다. 선형회귀 계수로 대체하지 않았다. 검증은 세 가지다. 두 정확한 근에서 $D^2 = 2\times10^{-16}$,
$\tau_Z = 1.0000000000$이고(허용오차 $10^{-10}$, $10^{-8}$), 구적 차수를 40에서 80으로 올려도 모든
표현에서 상대 변화가 $10^{-3}$ 아래이며, 상수 표현의 $\tau_Z = -0.760$이 몬테카를로로 독립 계산한
무조정 차이 $-0.759$와 일치한다. 공분산 대수의 내부 검사(tower property $\mathbb E[m_1\mid m_0]=m_0$)
결함은 $10^{-13}$ 이하다.

**평가 대상과 허용치는 실행 전에 고정했고, 사후에 뺀 것은 없다.** $S = \{1\}$, $r^* = 0.085786$.

순서로 구분하되 그 아래에서는 0 쪽으로 치우친다. 이 하한은 표본이 커지면 내려간다($n=12{,}000$에서는
$2.9\times10^{-3}$ 이상만 구분했다). 평가기가 "정확하다"는 라운드 5판의 문장은 철회했고,
"큰 불균형은 탐지하고 작은 불균형은 과소추정한다"로 대체한다.

### 단계 2. 학습 검증

학습·초기·정확 표현 셋을 **같은 감사행**에서 같은 평가기로 채점했다. 감사행은 인코더의 `fit`과 `val`
어느 쪽에도 들어가지 않았고, 평가 전에 교집합 0을 검사했다. "초기"는 실제로 선택된 restart의 시작
상태다(라운드 5판은 별도의 난수 초기값이었다). 학습된 표현은 선형이므로 그 **모집단** $D^2$와
$\tau_Z$를 단계 1의 방법으로 정확히 계산할 수 있고, 그 두 열이 이 표에서 가장 중요하다.

읽는 법.

- **개선은 손대지 않은 감사행에서 재현된다.** $n=48{,}000$에서 초기값 대비 $+0.01661$(se $0.00120$)이다.
  이번에는 감사행이 실제로 독립이므로 이 문장을 다시 쓸 수 있다.
- **감사 격차는 정확해와 구분되지 않는 곳까지 가지만, 모집단 $\tau_Z$는 아니다.** $48{,}000$에서 학습
  표현의 감사 격차는 $+0.00001$이고 모집단 $D^2$는 $8.8\times10^{-5}$로 단계 1의 탐지 하한 아래다.
  그런데 같은 표현의 $\tau_Z = 1.184$, 즉 **표현 오차 $0.18$이 남아 있다.** 감사가 볼 수 없는 크기의
  불균형이 결과 쪽에서 $0.18$의 편향으로 증폭된다. 단계 1의 $2r^*$ 행과 같은 현상이다.
- **표본이 커지면 표현 오차가 준다.** $\lvert\tau_Z - 1\rvert$가 $1.17 \to 0.71 \to 0.18$이다. 한 실행씩이므로
  추세의 불확실성은 7.1b가 다룬다.
- **분리 적합 비교 (F25).** augmented critic 전체를 자기 손실로 독립 적합한 감사 격차는 $48{,}000$에서
  $-0.00013$으로, 공유 파라미터 방식의 $+0.00001$과 같은 자리다. $4000$에서는 $+0.00237$ 대 $+0.00362$,
  $16{,}000$에서는 $+0.00097$ 대 $+0.00107$이다. 두 방식이 이 표본에서 같은 결론을 준다는 것까지만
  말한다.
- 학습 내부 수치도 정상이다. 검증 격차 $-0.00001$, $+0.00008$, $+0.00000$이고 인코더 갱신은 30, 96,
  282회다.

### 5.1 E1 격자: 열두 개 SCM 중 다섯 개

`results/probe_e1_s*.json`의 PROBE 출력(Algorithm 1의 최종값)에 대해, 비교군은 **강한 학습기**(L2
로지스틱 성향점수와 MLP 결과모형, 교차적합)로 다시 계산한 값만 쓴다. `EXPERIMENTS.md`가 명시하듯
나무 기반 학습기는 raw $(X,W)$의 성능을 크게 과소평가하므로 보고에 쓰면 안 된다. 라운드 5판의 이
절은 그 규칙을 어기고 나무 기반 수치를 썼고, 그래서 "다섯 설계 모두 승리"라는 틀린 결론을 냈다.
강한 비교군 수치는 이번에 `code/score_e1_strong_comparators.py`로 다시 계산해
`results/probe_e1_strong_comparators.json`에 저장했다.

**판정 기준은 계획서 1.3절의 것을 그대로 쓴다.** 반복 $r$의 절대오차를 $L_r(M) = |\hat\tau_r(M) - 1|$로
두고, 두 짝지은 대비

$$\Delta^{\rm raw}_r = L_r({\rm PROBE}) - L_r(X,W), \qquad
G^{\rm orc}_r = L_r({\rm PROBE}) - L_r(X,U,C) - 0.10$$

의 평균에 대한 $t$ 기반 95% 구간을 본다. raw를 이긴다는 것은 $\Delta^{\rm raw}$의 구간 상한이 $0$
아래인 것이고, oracle 기준을 통과한다는 것은 $G^{\rm orc}$의 구간 상한이 $0$ 아래, 즉 oracle 대비
초과 오차의 상한이 $0.10$ 이하인 것이다. **통계적으로 유의한 차이가 있다는 것과 이 기준을 통과한다는
것은 양립한다.** 라운드 5판은 이 둘을 혼동해 "oracle 동률은 어디에도 없다"고 적었다.

$n = 12{,}000$, 반복 20회, 평균 절대오차다.

## 6. 무엇이 확립되었고 무엇이 아직 아닌가

**확립된 것**

1. design F의 $D^2$와 $\tau_Z$ 기준값은 구조방정식에서 정확히 계산되며, 두 정확한 근에서 $D^2 = 0$,
   $\tau_Z = 1$이고 구적 차수에 안정적이다. (단계 1 (a)(b))
2. 참 함수형을 아는 지표 critic은 모든 대조의 기준값을 자기 표준오차 2배 안에서 회복한다. 기준값과
   평가 절차의 정의는 맞다. (단계 1 (d))
3. 신경망 평가기는 $n=48{,}000$에서 $D^2 \ge 2.4\times10^{-4}$인 불균형을 올바른 순서로 탐지한다. 그
   아래에서는 편향이 음수이며 seed 간 표준편차의 몇 배다. (단계 1 (c))
4. 선형 인코더의 적대적 학습은 독립 감사행에서 초기값 대비 개선을 재현하고, $48{,}000$에서 감사
   격차가 정확해와 구분되지 않는 곳까지 간다. (단계 2)
5. 정확한 표현을 주면 추정기는 oracle과 같은 자리에 도달한다. $32{,}000$에서 오차 $0.013$ 대
   oracle $0.009$. 학습된 표현을 주면 추정기는 그 표현의 $\tau_Z$로 $0.03$ 이내로 간다. **추정기는
   문제가 아니다.** (단계 3, 7.1)
6. 인과 오차는 거의 전부 표현 오차다. 그리고 표현 오차는 감사 격차가 탐지하지 못하는 크기의
   불균형에서 나온다. (7.1)
7. 후보 선택 논리는 균형 가능한 후보와 불가능한 후보를 참양성률 $1.00$, 거짓양성률 $0.06$으로
   분리한다. (5.3)
8. 기존 파이프라인의 s9 조정 설정은 계획서 기준을 강한 비교군으로 통과한다. (5.1)

**아직 아닌 것**

1. **새 구현으로 계획서 기준을 통과한 설정이 없다.** design F에서 학습된 표현은 $48{,}000$에서도
   중앙 오차 $0.14$, 다섯 실행 중 하나는 raw보다 나쁘다. DGP A 파일럿에서는 raw가 이긴다.
2. **표현 학습이 불안정하다.** 같은 자료, 같은 크기에서 optimizer seed만 바꿔도 오차가 $0.01$에서
   $0.49$까지 갈린다. 이것이 지금 가장 큰 문제다.
3. **감사 격차는 표현 오차를 인증하지 못한다.** design F에서 감사 신호의 최대가 $0.0105$이고 탐지
   하한이 $2\times10^{-4}$인데, 그 하한 아래의 불균형이 $0.1$–$0.4$의 인과 편향을 만든다. 스크리닝
   문턱값 $0.02$는 이 설계에서 무의미하다.
4. **F24 수정의 부작용.** DGP A에서 인코더 갱신이 최소 허용값 $20$에 붙는다. (5.3)
5. **s3, E4 MNIST, s10, s11, s12, DGP A는 raw에 진다.**
6. **확증 실행이 없다.** 계획서가 요구하는 50회 독립 반복은 어디에서도 실행되지 않았다.
7. **DGP D와 E, E2 블록 스윕, E3 비교군, E5 Twins, m-절제, 집계 경계 계산이 남아 있다.**

## 7. 단계 4와, 이번 실험에서 가장 중요한 발견

### 7.1 고정 자료에서 optimizer seed만 바꾸면

라운드 6 리뷰의 P2 순서대로, 먼저 **자료 하나를 고정**하고 학습의 optimizer seed만 다섯 번 바꿨다.
추정행 $32{,}000$개는 크기 사이에서 고정이고, 작은 학습 표본은 큰 학습 표본의 앞부분(부분집합)이다.
따라서 한 열 안에서 달라지는 것은 "같은 자료를 인코더가 얼마나 봤는가"뿐이다. 각 칸마다 학습된 선형
표현의 모집단 $D^2$와 $\tau_Z$를 단계 1의 방법으로 정확히 계산했으므로, 인과 오차를

$$|\hat\theta - 1| \;\le\; \underbrace{|\tau_Z - 1|}_{\text{표현 오차}} + \underbrace{|\hat\theta - \tau_Z|}_{\text{추정 오차}}$$

로 분해할 수 있다. `results/dgp_f_staged_r6_s4_fixed_data.json`, 재계산은 `code/summarize_stage4.py`.

| 학습 표본 | 칸 | $\lvert\hat\theta-1\rvert$ 중앙값 | p90 | 최대 | $\lvert\tau_Z-1\rvert$ 중앙값 | p90 | $\lvert\hat\theta-\tau_Z\rvert$ 중앙값 | 최대 | 모집단 $D^2$ 중앙값 | 감사 격차 중앙값 | seed 간 sd | raw 이김 | raw | 정확해 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 3,000 | 5 | 0.9485 | 1.8439 | 1.8806 | 0.9817 | 1.8669 | 0.0239 | 0.0332 | 4.7e−03 | +0.00531 | 0.5235 | 0/5 | 0.3877 | 0.0162 |
| 12,000 | 5 | 0.3446 | 0.4288 | 0.4846 | 0.3409 | 0.4438 | 0.0038 | 0.0305 | 8.2e−04 | +0.00067 | 0.2043 | 4/5 | 0.3877 | 0.0162 |
| 48,000 | 5 | 0.1449 | 0.3388 | 0.4194 | 0.1629 | 0.3497 | 0.0150 | 0.0181 | 1.4e−04 | −0.00008 | 0.1333 | 4/5 | 0.3877 | 0.0162 |

읽는 법. 네 가지가 같은 표에서 읽힌다.

1. **인과 오차는 거의 전부 표현 오차다.** 모든 크기에서 $\lvert\hat\theta - \tau_Z\rvert$의 최대값이
   $0.033$ 이하인 반면 $\lvert\tau_Z - 1\rvert$의 중앙값은 $0.98$, $0.34$, $0.16$이다. 추정기는 표현이
   가리키는 곳으로 정확히 가고, 문제는 표현이 가리키는 곳이다. 이것이 라운드 6 리뷰가 요구한 "균형
   학습 실패, 표현의 잔여 편향, 최종 추정 오차의 분리"다.
2. **같은 자료, 같은 크기에서 optimizer seed만 바꿔도 오차가 크게 갈린다.** $12{,}000$에서 다섯 실행의
   $\lvert\hat\theta - 1\rvert$는 $0.011$, $0.058$, $0.345$, $0.345$, $0.485$다. seed 간 표준편차가
   $0.20$이고, 이것은 raw와의 차이($0.39 - 0.34$)보다 크다. 표현 학습 절차 자체가 불안정하다.
3. **표본이 커지면 중앙값과 퍼짐이 같이 준다.** 중앙값 $0.95 \to 0.34 \to 0.14$, seed 간 sd
   $0.52 \to 0.20 \to 0.13$. 그러나 $48{,}000$에서도 다섯 중 하나는 $0.42$로 raw보다 나쁘다.
   유한한 세 크기에서의 감소이며, 수렴의 증명이 아니다. `passed` 판정은 두지 않았다.
4. **감사 격차는 표현 오차를 보지 못한다.** $48{,}000$에서 감사 격차 중앙값은 $-0.00008$, 모집단 $D^2$
   중앙값은 $1.4\times10^{-4}$로 단계 1의 탐지 하한 근처다. 그런데 같은 표현들의 $\lvert\tau_Z - 1\rvert$
   중앙값은 $0.16$이다. 감사가 "완벽"이라고 말하는 표현이 $0.16$의 편향을 남긴다.

**라운드 5판과의 차이.** 라운드 5판의 같은 표는 감사행이 인코더 학습행과 100% 겹친 채 계산됐고,
seed 반복도 자료와 optimizer seed를 함께 바꿨다. 그 표의 감사 격차는 무효이고, 오차 값은 이 표로
대체한다. 라운드 5판이 "수렴"이라 부른 것은 이 표에서 "유한한 세 크기에서의 감소, 큰 퍼짐 동반"으로
바뀐다.

  중앙값 $\le 0.05$, p90 $\le 0.10$이다. 현재 $48{,}000$의 값은 중앙값 $0.105$, p90 $0.323$이다.
  이 기준은 아직 동결되지 않았고, 동결 뒤에 판정해야 한다.
- 반복 3회는 신뢰구간을 말할 크기가 아니다. 이 표는 방향과 규모를 보여주며, 리뷰가 요구한 data seed
  10개 × optimizer seed 5개는 다음 단계다.

### 7.2 왜 그런가: 감사 신호와 결과 규모의 비율

design F에서 처치 확률과 결과 방정식은 서로 다른 방식으로 $U$에 반응한다.

- 처치 쪽: $P(A=1 \mid \cdot) = 0.05 + 0.9\,\mathrm{expit}(U + 3I + 0.2X + 0.3C)$.
  $Z$가 설명하지 못하는 $3I$ 때문에 조건부 확률은 표준편차 $3$ 이상인 정규분포 위에서 expit을
  평균낸 값이 된다. 이 평균은 매우 평탄하다. $U$에 대한 정보가 조금 바뀌어도 확률은 거의 안 움직인다.
- 결과 쪽: $Y(a) = a - 4U + 0.2X - 0.5C + \varepsilon$. 여기에는 평탄화가 없다. $U$의 불균형이
  그대로 $-4$ 배로 편향에 들어간다.

이 둘을 같은 눈금에 놓고 계산했다. 각 $r$에 대해 모집단 $D^2$와, $Z$로 선형 조정한 뒤 남는
$U$의 불균형, 그리고 그 불균형이 만드는 결과 편향이다.

| $r$ | 모집단 $D^2$ | $D = \sqrt{D^2}$ | $U$ 불균형 | 결과 편향 |
| ---: | ---: | ---: | ---: | ---: |
| 0.08579 (정확해) | 0.000002 | 0.00134 | −0.00097 | +0.0039 |
| 0.00000 | 0.000311 | 0.01763 | +0.07710 | −0.3084 |
| 0.17157 | 0.000220 | 0.01483 | −0.07541 | +0.3016 |
| 0.50000 | 0.002866 | 0.05353 | −0.29361 | +1.1744 |
| 1.00000 | 0.003627 | 0.06023 | −0.37679 | +1.5072 |

두 번째 줄을 보라. $D^2 = 0.00031$인 표현이 $-0.31$의 결과 편향을 만든다. 그런데 단계 1에서
확인한 대로, **$D^2 = 0.0003$은 $n = 48{,}000$에서도 평가기가 $0$과 구분하지 못하는 크기다.**
단계 4에서 관측된 오차 $0.20$–$0.29$가 정확히 이 구간에 있다.

### 7.3 이론과 대조하면

원고 `manuscript/main/4.tex`의 end-to-end 민감도 결과는 오차를 이렇게 묶는다.

$$|\widehat\tau_j^{\mathrm{AIPW}} - \tau| \;\le\; \varepsilon_{\mathrm{AIPW},j}
\;+\; \frac{\Gamma_j(\widehat\phi_j)}{\eta(1-\eta)} \, D_{\mathrm{res},j}(\widehat\phi_j)$$

여기서 $\eta$는 성향점수의 상하한 상수로 $\eta \le e \le 1-\eta$를 만족한다. design F의 참
성향점수는 구조적으로 $[0.05, 0.95]$에 있으므로 $\eta = 0.05$이고 $\eta(1-\eta) = 0.0475$,
즉 계수가 $21.1$이다.

위 표에서 실제로 관측된 비율, 즉 결과 편향을 $D$로 나눈 값은 $-0.3084/0.01763 = -17.5$와
$0.3016/0.01483 = 20.3$이다. 경계가 주는 계수는 $\Gamma_j \times 21.1$이므로, **관측된 값은
$\Gamma_j$가 $0.8$에서 $1.0$ 사이일 때 경계가 거의 그대로 달성되는 상황에 해당한다.**
$\Gamma_j$는 관측 자료에서 식별되지 않으므로 이것을 "경계가 빡빡하다"의 증명으로 쓸 수는 없다.
말할 수 있는 것은 이것이다. **$1/\{\eta(1-\eta)\} = 21.1$이라는 계수가 있는 한, 감사에서 보이지
않을 만큼 작은 $D$도 인과 오차를 작게 묶어주지 못한다.**

**결론**: PROBE의 감사 기준은 작동한다. 다만 design F에서는 그 기준이 인과 오차를 충분히 강하게
묶지 못한다. 감사에서 보이지 않는 크기의 불균형이 결과 방정식의 $-4U$를 통해 크게 증폭되기 때문이다.

### 7.4 이것이 뜻하는 바

이 발견은 세 가지를 바꾼다.

1. **설계 재검토가 필요하지만, 이전 보고서의 계수 변경 제안은 철회한다.** 이전 판에서 $I$의 계수를
   $3 \to 1.2$로, 결과의 $U$ 계수를 $-4 \to -1$로 바꾸자고 적었다. 라운드 6 리뷰가 두 가지를
   지적했고 둘 다 직접 계산으로 확인했다.
   - 두 변경을 함께 적용하면 무조정 처치군 차이가 현재의 $-0.759$에서 $+0.444$로 바뀐다. 참 효과가
     $+1$이므로 **요구 조건인 Simpson 부호 역전이 사라진다.**
   - 균형 방정식 $r^2 - 1.2r + 1/k = 0$의 판별식 $1.44 - 4/k$는 $k = 1, 2$에서 음수다. 남은 측정값이
     하나 또는 둘인 다섯 개 조합에서 알려진 정확한 표현을 잃는다.
   참고로 $I$ 계수만 $1.2$로 낮추면 역전은 남지만($-1.660$) 근 문제는 그대로이고, $I$ 계수를 $2.0$으로
   두면 모든 $k$에서 실근이 있다($k=1$은 중근). 어떤 재설계든 **부호 역전과 실근 존재를 둘 다** 미리
   확인해야 하며, 이 보고서는 재설계를 제안하지 않는다. 현재 F의 계수는 그대로 둔다.
2. **스크리닝 문턱값을 설계마다 따로 정해야 한다.** 지금은 `SCREEN_CONST = 0.02`로 고정인데,
   design F에서 계산한 열한 개 표현의 최대 신호가 $0.0105$다.
3. **감사 격차만으로 "이 표현은 충분하다"고 말할 수 없다.** 보고할 때는 감사 격차와 함께 그 격차가
   허용하는 인과 편향의 크기를 같이 적어야 한다. 단위를 정확히 쓰면, 단계 4에서 관측된 감사 격차는
   $D^2 \approx 5\times10^{-4}$이고 따라서 $D \approx 0.022$다. 경계 $\Gamma D/\{\eta(1-\eta)\}$는
   $\Gamma \times 0.47$이다. 이전 판에서 이것을 "$D = 0.0005$"로 적은 것은 $D^2$와 $D$를 혼동한
   오류이며 여기서 바로잡는다. $\Gamma$는 관측 자료에서 식별되지 않으므로 이 경계는 관측된 편향의
   원인을 확정하지 않는다. 확정된 것은 **작은 감사 격차와 큰 인과 오차가 함께 관측된다**는 사실까지다.
   원인의 분리는 7.1b의 새 분해, 즉 학습된 표현의 모집단 $\tau_Z$ 계산으로 한다.

### 7b.1 계수 하나만 학습하는 진단

표현을 $Z_r = (X, C, \overline M_4 + rI)$로 고정하고 **학습 가능한 파라미터를 $r$ 하나로** 만들었다.
정확해는 $r^2 - 3r + 1/4 = 0$의 두 근이고 작은 쪽이 $0.085786$이다. 같은 자료, 같은 전처리, 같은
critic 구조와 예산에서 네 가지가 각각 어떤 $r$을 고르는지 비교했다. 격자는 $[-0.5, 1.5]$의 21점으로,
시작값 $r = 0$과 함께 **실행 전에 고정했다.** 참 근과 참 확률은 진단으로만 쓰고 학습 경로에 넣지
않았으며, 그 사실을 소스 검사로 잠갔다.

$n = 24{,}000$, 독립 자료 5개, optimizer seed 5개다. 원고 모드다.

해상도"를 지목했던 것은 철회한다. $24{,}000$에서 참 확률을 쓴 유한표본 목적은 정확해를 단일 최소점
으로 집어낸다.

**격자 해상도 주의.** 격자 간격이 $0.1$이고 참 근이 $0.0858$이므로, 격자가 낼 수 있는 최소 편향이

비교군의 $\tau_Z$가 저장되며, 결과 파일이 checkpoint digest까지 검증된다는 뜻이다.

**주의할 대비 하나.** 계수를 하나로 줄인 학습기($9{,}600$ 학습행)의 편향 중앙값이 $0.24$인데, 전체
선형 인코더($24{,}000$ 학습행)는 $0.10$이다. **파라미터를 하나로 줄여도 최적화가 나아지지 않았다.**
문제는 차원이 아니라 이 목적 위에서의 탐색 동역학이다.

**성능 FAIL은 이 실험의 결론이지 실험의 실패가 아니다.** 구현과 진단이 PASS이므로 이 FAIL은 믿을 수
있는 음성 결과다. 그리고 진단이 그 원인을 한 곳으로 좁혔다.

### 7b.4 이것이 바꾸는 것

다음 작업은 목적함수를 바꾸는 것이 아니라 **탐색 방법을 바꾸는 것**이다. 저차원 매개화에서는 격자가
매번 좋은 값을 찾으므로, 일반적인 경우에도 다중 시작점, 거친 격자에서 세밀한 격자로 좁히기,
또는 미분을 쓰지 않는 탐색이 후보다. 이것은 원고 4절의 목적함수를 그대로 두고 그 최소화 절차만
바꾸는 변경이므로 이론을 건드리지 않는다.

## 7c. 라운드 10: 공통 split-sample refit 목적 재채점과 계층 판정

라운드 10은 원고 모드와 변형 모드 모두에서 격자 $21$점과 optimizer가 학습한 $r$을 **같은 critic
규약**으로 새로 채점했다. base critic과 augmented critic은 각자의 Brier 위험으로 독립 조기 종료하며,
선택용 표본과 손대지 않은 감사 표본의 목적을 모두 저장한다. 실행 전에 고정된 것은
`고정 grid와 학습된 r_hat을 합친다`는 **후보 생성 규칙**이다. 학습된 $r$과 실현 후보 집합은
자료와 optimizer seed에 따라 달라진다. 목적의 동점은 모두 보존하고, 실제 한 점이 필요할 때만
$|r|$이 작은 것, 그다음 $r$이 작은 것 순서로 고른다. 이 동점 규칙은 인과 성공을 보장하지 않는다.

### 7c.2 계수 진단

아래는 현행 PASS 증거가 아니라 보존된 라운드 10 파일의 **비인증 사후 진단**이다. 성공은 확증 기준이
아니라 진단용 기준 $|\tau_Z-1|\le 0.11$이다. “공통 fitted critic” 행은 학습 모드와 무관하게 같은
split-sample refit 규약을 쓰므로 두 모드에서 같다. 이를 원고의 모집단 목적 또는 동결된 이론 목적이라고
부르지 않는다.

| 진단 가설 | 비인증 기술 판정 | 근거의 한계 |
| --- | --- | --- |
| 모집단 격자가 인과 성공 후보를 선택한다 | **SUPPORTED** | 5/5지만 design F의 고정 격자 진단에 한정 |
| 참 확률 split-sample 격자가 인과 성공 후보를 선택한다 | **SUPPORTED** | 5/5지만 참 확률은 학습에 쓸 수 없는 privileged 진단 |
| optimizer가 자기 유한후보 최소값을 크게 놓친다 | **NOT_SUPPORTED** | 선택 regret 중앙값과 p90이 작으며 전역 최적화 bound가 아님 |
| fitted-critic 어긋남이 critic 근사와 표본 변동 중 어디에서 왔다 | **UNRESOLVED** | 현재 저장값은 두 원인을 분리하지 않음 |

이 네 라벨은 `results/dgp_f_r10_verdicts.json`의
`non_authoritative_descriptive_hypotheses`에 기록된다. 엄격 판정의 `hypotheses` 네 항목은 모두
`NOT_EVALUATED`이며, 위 표가 그것을 우회하지 않는다.

| 선택 층 | 편향 중앙값 | 최소–최대 | 성공 | data seed별 동점 수 |
| --- | ---: | ---: | ---: | --- |
| 모집단 목적 | 0.0505 | 0.0505–0.0505 | 5/5 | 1, 1, 1, 1, 1 |
| 참 확률 유한표본 목적 | 0.0505 | 0.0505–0.0505 | 5/5 | 1, 2, 1, 1, 1 |
| 공통 fitted-critic 목적 | 0.3122 | 0.0505–0.3910 | 1/5 | 1, 1, 1, 2, 2 |
| 원고 모드 optimizer, 25칸 | 0.2158 | 0.0200–0.3097 | 2/25 | 해당 없음 |
| 변형 모드 optimizer, 25칸 | 0.3640 | 0.0525–0.4179 | 2/25 | 해당 없음 |

실제로 `grid ∪ learned r_hat`에서 공통 선택 규칙이 반환한 data seed별 편향은 원고 모드에서
$0.3910, 0.3910, 0.3122, 0.1115, 0.3122$로 성공이 $0/5$다. 변형 모드에서는
$0.4179, 0.3910, 0.3122, 0.0505, 0.3122$로 $1/5$다. 원고 모드의 네 번째 값 $0.1115$는
문턱 $0.11$을 조금 넘으므로 실패로 세었다.

원고 모드 optimizer가 낸 점의 **유한후보 경험적 regret**은 선택 표본에서 중앙값 $0.000169$,
p90 $0.000741$이고, 진단용 감사-최소 regret은 중앙값 $0$, p90 $0.000706$이다. 변형 모드도 각각
$0.000268$, $0.000907$과 $0$, $0.000628$이다. 이것은 전역 최적화 regret이나 이론의
$\epsilon_{\rm enc}$가 아니다. 특히 감사-최소 regret은 감사 자료에서 사후로 최소 후보를 다시 고른
진단량이지, 선택 표본에서 고른 후보를 감사 표본에 고정해 비교한 정직한 선택 regret이 아니다.

**해석.** optimizer가 좋은 $r$을 자주 놓치는 것은 사실이다. 그러나 optimizer가 내놓은 후보도 공통
목적의 최솟값에 거의 붙어 있고, 공통 fitted-critic 격자 자체도 다섯 자료 중 네 자료에서 인과적으로
나쁜 점을 고른다. 그러므로 현재 자료는 “좋은 해가 경험적 목적에서 보이는데 optimizer만 못 찾는다”를
지지하지 않는다. 더 강하게 지지되는 설명은 작은 목적 차이가 큰 $\tau_Z$ 차이를 안정적으로 순위화하지
못한다는 것이다. 이것이 critic의 근사 오차인지, 표본 변동인지, 둘의 상호작용인지는 아직 분리하지
못했다.

### 7c.3 stage 4의 계층 집계 (비인증 기술통계)

optimizer seed는 독립 자료 반복이 아니다. 따라서 각 data seed 안의 세 optimizer 값을 먼저
중앙값으로 합치고, 그렇게 얻은 data-seed 값 세 개의 중앙값과 p90을 보고한다. 괄호 안의 pooled p90은
아홉 optimizer 칸을 직접 합친 변동 진단값이며 성능 판정에 쓰지 않는다.

| $n$ | 학습행 | $|\hat\theta-1|$ 중앙값 / p90 | $|\tau_Z-1|$ 중앙값 / p90 | pooled p90 | $|\hat\theta-\tau_Z|$ 중앙값 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 3,000 | 1,500 | 0.6885 / 0.9666 | 0.6365 / 0.9622 | 1.6570 | 0.0111 |
| 12,000 | 6,000 | 0.2905 / 0.5804 | 0.2784 / 0.5475 | 0.6404 | 0.0124 |
| 48,000 | 24,000 | 0.1271 / 0.1326 | 0.1001 / 0.1116 | 0.1803 | 0.0126 |

$n=48{,}000$의 data-seed별 $|\tau_Z-1|$ 중앙값은 $0.114454$, $0.090579$, $0.100149$다.
세 data seed의 모든 optimizer 칸이 raw보다 총오차가 작았고, raw 총오차 중앙값은 $0.3877$이었다.
이는 이 파일럿의 유리한 비교 결과지만, $3$개 data seed만으로 보편적 우월성이나 수렴을 주장할 수 없다.

### 7c.4 증거의 경계

- `complete: true`와 마지막 로그의 정상 요약은 확인했다. 그러나 새 strict validator는 checkpoint-cell
  소유권 metadata 부재 때문에 거절한다. 별도의 OS-level 종료 코드도 결과 파일에 보존되지 않았다.
- 각 실행은 자기 run 디렉터리에 소스 원문과 manifest를 보존했다. 두 계수 실행의 snapshot bundle은
  각각 6개 파일, stage 4는 5개 파일이다. 새 verifier는 manifest가 주장하는 bundle hash를 믿지 않고
  정확한 필수 role과 role별 digest에서 bundle을 다시 계산한다.
- 사후 verifier 강화로 현재 `coefficient_probe.py`, `provenance.py`, `staged_dgp_f.py`는 계수 실행
  snapshot과 `CURRENT_DIFFERS`다. stage 4 snapshot에서는 `provenance.py`, `staged_dgp_f.py`가 다르다.
  이는 역사적 snapshot의 byte 무결성을 훼손하지 않지만, 라운드 10을 현재 코드의 실행이라고 부르지
  않는다.
- 이 결과는 design F, $S=\{1\}$, 제한된 계수 진단과 선형 stage 4에 관한 개발 결과다. 모든 $30$개
  split을 쓰는 Algorithm 1, DGP A–E, 이미지 표현, 확증 $50$회 결과로 외삽하지 않는다.

## 8. 모니터링 에이전트를 위한 검증 항목

이 절은 내 주장을 반박하려는 독자를 위한 것이다. 확인할 수 있는 형태로 적었다.

### 8.1 내가 주장하지 않는 것

- 확증 결과를 얻었다고 주장하지 않는다. 모든 실행이 파일럿이고, 요약기가 `headline_ready: false`를
  돌려준다.
- 단계별 실험의 숫자를 본 결과로 쓰겠다고 주장하지 않는다. 선형 인코더와 3차원 표현은 계획서 8.4절과
  다르고, 진단 목적의 의도적 이탈이다.
- PROBE가 모든 설계에서 raw를 이긴다고 주장하지 않는다. s3와 E4 MNIST에서는 진다.
- design F의 계수 변경을 제안하지 않는다. 라운드 5판의 제안은 철회했다 (7.4, 8.2).
- 단계 4의 유한한 몇 크기에서 오차가 줄어든 것을 수렴의 증명이라고 부르지 않는다. `passed` 판정도
  제거했다. 보고하는 것은 크기별 분포와 그 퍼짐이다.
- optimizer seed를 독립 반복으로 세지 않는다. 통계적 반복 단위는 data seed다. 고정 자료에서 optimizer
  seed를 바꾼 결과는 한 학습 절차의 변동성을 재는 용도로만 쓴다.
- 단계 1의 신경망 평가기가 "불편"이라고 주장하지 않는다. 주장하는 것은 탐지 하한(detection floor)과,
  그 아래에서 추정이 0 쪽으로 치우친다는 사실이다.
- 이 작업을 Dropbox에 반영하거나 commit, push하지 않았다. 지시받지 않았다.
- `decoupled_critic_fit`(F25의 분리 적합 비교)을 본 파이프라인 `run_dgp_ae.py`에는 넣지 않았다.
  후보마다 critic을 한 벌 더 적합해야 해서 실행 시간이 두 배 가까이 늘기 때문이다. 단계별 연구에서만
  호출하며, 이것은 의도한 범위 결정이다.

### 8.2 철회하거나 정정한 서술

라운드 5와 6에 걸쳐 철회한 것을 한곳에 모은다. 각 항목은 무엇이 틀렸고 무엇으로 대체됐는지 적는다.

1. **"학습에 쓰지 않은 자료에서 개선이 재현됐다" (라운드 5판 단계 2·4) — 철회.** 평가 함수가
   전체 자료를 다른 seed로 다시 나눴기 때문에, $n = 48{,}000$의 평가행 12,000개 중 8,952개(74.6%)가
   encoder 학습 또는 checkpoint 선택에 쓰인 행이었다. 단계 4의 학습 표현 평가는 100% 겹쳤다. 최종
   인과효과 추정에 쓴 행은 이 경로로 겹치지 않았으므로, 영향은 감사 격차 평가에 한정된다. 이번 판은
   encoder가 쓴 분할 인덱스를 끝까지 전달하고, 평가 전에 교집합이 0임을 검사로 강제한다.
2. **"평가기가 모집단 참값과 $2\times10^{-5}$ 이내로 일치하고 거의 불편이다" — 철회.** 같은 표 안에
   기준 $D^2 = 0.000236$인 표현을 $-0.000026$(보고된 표준오차 $0.000012$)로 추정한 행이 있었다.
   차이가 보고된 표준오차의 22배다. 확인된 것은 **큰 불균형은 탐지한다**는 사실이고, 작은 불균형에서는
   추정이 0 쪽으로 치우치며 보고된 표준오차가 그 오차를 담지 못한다. 이번 판의 단계 1은 optimizer
   seed를 바꿔 다섯 번 적합한 퍼짐을 불확실성으로 쓰고, 기준값은 표본이 아니라 구조방정식에서 계산한다.
3. **"E1 다섯 설계 모두에서 PROBE가 raw를 이긴다" — 철회.** 나무 기반 보조모형으로 계산된 raw
   수치를 썼다. `EXPERIMENTS.md`가 명시한 대로 그 수치는 raw를 과소평가하며 보고에 쓰면 안 된다.
   강한 학습기 기준으로 s10, s11, s12에서 **PROBE가 raw에 진다.** 정정된 성적표는 5.1절이다.
4. **"oracle 동률은 어디에서도 달성하지 못했다" — 정정.** 계획서의 기준은 oracle 대비 초과 오차의
   신뢰구간 상한이 $0.10$ 이하인 것이다. s9 조정 설정은 초과 오차 $0.040$, 구간 $[0.018, 0.061]$로
   **이 기준을 통과한다.** 통계적으로 유의한 차이가 있다는 사실과 기준을 통과한다는 판정은 양립한다.
   다만 이것은 이전 파이프라인의 결과이고 새 neural Brier 구현의 성공으로 옮겨 쓸 수 없다.
5. **design F 계수 변경 제안 — 철회.** 7.4절에 이유가 있다. Simpson 역전이 사라지고 다섯 조합에서
   정확한 표현을 잃는다.
6. **"$D = 0.0005$" — 정정.** $D^2 = 0.0005$이고 $D = 0.022$다.
7. **"증폭 계수 21.1로 원인 확정" — 낮춘다.** 경계에는 식별되지 않는 $\Gamma$가 함께 들어간다.
   관측된 것은 작은 감사 격차와 큰 인과 오차의 동시 발생까지이며, 원인 분리는 이번 판의 모집단
   $\tau_Z$ 분해로 한다.
8. **단계 4의 "수렴" 판정 — 철회.** 크기마다 한 실행이었고, 그 뒤의 seed 반복도 자료와 optimizer
   seed를 함께 바꿨다. 이번 판은 두 seed를 분리하고, 마지막 오차가 첫 오차보다 작다는 조건으로
   `passed`를 주지 않는다.
9. **F20 서술 (라운드 5) — 정정.** "공유 파라미터를 사용하는 학습 방식으로 변경했고, 이번 표본에서
   성능이 개선됐다."
10. **DGP A 파일럿에서 PROBE가 raw를 이긴다 (라운드 5판 초안) — 정정.** raw가 이긴다.

### 8.4 내가 틀렸을 가능성이 가장 큰 지점

1. **단계 1의 모집단 $D^2$ 계산.** 결합정규 가정과 공분산 추정이 맞아야 한다. 공분산을 $300{,}000$행
   표본에서 경험적으로 추정하므로, 이 열 자체에 표본오차가 있다. 표에 표준오차를 같이 실었고 모두
   $10^{-5}$ 이하지만, 계산 자체가 틀렸을 가능성은 이 표준오차가 잡아주지 않는다.
   독립 검증 방법: $r = r^*$와 $r = $ 두 번째 근에서 모두 정확히 $0$이 나오는지 본다. 두 근이
   같은 이차방정식의 해이므로 둘 다 $0$이어야 하고, 실제로 둘 다 $0.000000$이다.
2. **단계 2의 "구분되지 않는다"는 판정.** 학습된 표현의 감사 격차 $-0.00008$(se $0.00009$)이
   정확해의 $+0.00000$(se $0.00001$)과 구분되지 않는다고 적었다. 그러나 단계 3에서 같은 방식으로
   학습한 표현이 $+0.117$의 인과 편향을 남겼다. **감사 격차가 0에 가깝다는 것이 인과 편향이 0이라는
   뜻이 아니다.** 이 설계에서는 감사 신호의 상한 자체가 $0.005$로 작기 때문에, 감사로는 보이지 않는
   표현 오차가 인과 추정에서는 크게 보일 수 있다. 이것이 이 보고서에서 가장 중요한 한계다.
3. **단계 3과 4의 교차적합 방식.** 2-겹 교차적합을 쓴다. 계획서의 3-겹 회전과 다르다. 표준오차가
   약간 클 수 있다.
4. **후보 선택 논리의 평가 기준.** `balance_feasible`은 내가 구조에서 유도한 판정이지 실험에서
   측정한 것이 아니다. 이 판정이 틀리면 참양성률과 거짓양성률이 모두 무의미해진다. DGP A–E에 대한
   유도는 `probe_dgp_ae.py`의 `balance_feasible` docstring에 적혀 있고, design F는 `f_exact_representation`이
   실제로 $0$ 격차를 내는 것으로 확인된다.

## 10. 다음에 할 일

라운드 11에서 provenance와 판정 집계의 결함을 고친 producer로 재실행했고 implementation PASS를
얻었다. 동결 기준은 변경하지 않았다. 다음 최소 실험은 **split-sample refit 목적이 왜 인과적으로 좋은
$r$을 순위화하지 못하는지 분해하는 것**이다.

1. **critic 근사와 표본 변동을 분리한다.** 현재 다섯 data seed에서 각 후보의 모집단 $D^2$, 참 확률
   유한표본 목적, 공통 critic의 선택 목적과 감사 목적이 모두 저장돼 있다. 후보별로
   `common audit − true-probability audit`와 data-seed 간 분산을 먼저 표로 내고, critic 용량을 늘리는
   실험은 그 차이가 지배적인 경우에만 한다.
2. **후보 순위의 안정성을 직접 측정한다.** 좋은 후보 $r=0.1$과 실제 선택 후보의 목적 차이 및 paired
   불확실성을 저장하고, seed별 순위가 재현되는지 본다. 절대 목적값이 작다는 이유만으로 균형이나 인과
   성공을 판정하지 않는다.
3. **optimizer 개입은 그다음이다.** split-sample refit 목적이 좋은 후보를 안정적으로 1위에 놓는 조건을 찾은 뒤에만
   다중 시작점이나 미분 없는 탐색을 비교한다. 현재 regret가 작은 결과에서는 탐색 개선만으로 해결된다고
   예측할 근거가 없다.
4. **stage 4는 기준을 유지한 채 반복 수를 늘린다.** 현재 독립 data seed가 세 개뿐이므로, 새 프로토콜과
   새 run ID로 data seed를 늘려 $n=48{,}000$의 계층 중앙값과 p90을 다시 잰다. 기존 세 seed를 보고
   기준이나 표본 크기를 고르지 않는다.
5. **본 실험으로의 확장은 마지막이다.** design F의 제한 진단과 stage 4가 안정된 뒤에야 모든 $30$개
   split, DGP A–E, 이미지, 확증 $50$회로 간다. 과거 s9의 성공은 별도 파이프라인 근거로 유지하되,
   이번 neural Brier 구현의 성공으로 합치지 않는다.
